# Visuals and Formatting

## Contents

1. Visual plan

4. Placement and production
5. Markdown formatting

## 1. Visual Plan

开始写作前完成内部视觉规划，明确每张图回答的投资问题、所在章节、数据来源、期间、单位和证据层级。不要把视觉规划写成正文中的独立章节。

优先审计公司官网、数据手册、投资者演示、SDK/Release Notes、开发者大会、展会方案、客户案例和合作伙伴资料。候选视觉分为产品/架构、公司自测、产品路线图、生态/客户案例和营销展示。

公司自测必须标注测试主体和已披露的模型、精度、功耗、批量、输入长度、软件版本或环境。条件不完整时不得与竞品直接排名。

路线图只能证明规划，不能证明流片、回片、送样、量产或收入。营销展示不能支持订单、份额或技术领先结论。

## 2. Minimum Deliverables

完整模式通常需要 5—8 个高价值视觉，至少包含：

1. 营收拆分图：最新完整财年，优先覆盖按产品/业务和按区域两种口径，标明金额、占比、期间、单位和来源。
2. 需求/兑现流程图：从真实需求、采购、认证/导入和订单/拉货，传导到收入、毛利率和现金流。
3. 产业位置图：选择产业链、工艺、产品矩阵、技术路线或竞争分层中最能说明公司位置的一种。
4. 量化趋势图：使用一手数据重绘收入、利润、毛利率、订单、产能、销量、ASP、库存、现金流或关键运营指标。

缺少可比时间序列时，不得想象数据。保留其他核心视觉，并明确趋势数据缺口。

## 3. Evidence Boundaries

- 每张数据图标明指标口径、期间、单位、来源和证据层级。
- 一手数据、券商估算和研究推演不得画成同一确定口径。
- 榜单、TAM、参数和路线图不能冒充订单、收入或份额。
- 外部英文图表优先翻译重绘；保留原图时提供中文解释和原始出处。
- 同行财务图命名为经营位置、规模或盈利能力，不得误称市场份额。

## 4. Placement and Production

图表放进直接支持的章节：

- 营收拆分图放在公司基本情况前部。
- 需求传导图放在第一性原理或生命周期。
- 产业/产品图放在行业或竞争章节。
- 公司趋势图放在订单、财务或估值章节。

图前写一句要证明的结论，图后写“看图要点”说明其投资含义（默认不超过 3 句/约 80 字；信息多时改用 3—4 行小表：看图 / 读数 / 含义）。不要另建“图表补充”集中堆图。

复杂中文文字图优先使用确定性绘图或 Mermaid。Mermaid 主流程通常不超过 8—10 个节点；过宽或分支过多时拆图。静态数据图优先 PNG，检查中文、图例、单位、来源、宽度和裁切。

图片放在报告项目的 `_图表`、`_截图` 或用户指定的稳定子目录，用相对路径引用。不得引用创建者个人电脑的绝对路径。

## 5. Markdown Formatting

一级章节统一使用 `#`，二级和三级依次使用 `##`、`###`。正文第一行不放标题页、日期、文件夹或免责声明块。

分析型表格严格控制在 3—4 个主题行，不设 5—6 行版本：任何对象拆到 3—4 个维度已经够用。先归并上位主题，再在单元格中保留细节：

```markdown
1. **小标题**：第一句。<br>第二句。
<br><br>
2. **小标题**：第一句。<br>第二句。
```

- 不同加粗小标题之间用 `<br><br>`；同一小标题下的不同句子用单个 `<br>` 分行。
- 单元格里出现分号、并列或转折后还有独立句子时，每句单独一行，不要挤在同一行。
- 财务时间序列、型号清单、时间轴和资料来源可以超过 4 行，但应在表前或表后提供 3—4 行归纳。

避免连续 150 字以上的大段。优先采用“核心判断 + 2—4 个短要点/小表格 + 收束句”；遇到分号、并列或转折后还有独立句子的段落，优先改成表格。

使用两级重点：

- `**加粗**`：表格小标题、关键数字和局部关键词。
- `**<u>加粗并下划线</u>**`：公司本质、核心矛盾、关键验证变量、兑现缺口、估值核心假设和反证信号。

不要整段加粗或下划线，也不要把“待确认”包装成确定结论。完稿前检查 `<u>` 标签成对。

默认只交付 Markdown。只有用户明确要求时才导出 PDF；导出后检查目录、书签、图片页、表格页、裁切和空白页。
